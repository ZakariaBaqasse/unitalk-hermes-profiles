| Field | Value |
|---|---|

| **Band** | `None` |
| **Block reason** | `Candidate exclusion_status is excluded.` |
| **Outcome** | `excluded` |

### How the block was reached

The calculator hit line 102-103 of `calculate_icp_score.py`:

> `if qualification.get("exclusion_status") == "excluded":`
> `→ return blocked_result(...)`

This fires **before** any positive criteria are evaluated, because the candidate's `qualification.exclusion_status` is already set to `"excluded"` from the earlier qualification step. No positive weights are consulted, no components are built, no band cap is applied — the result is a clean block with the `"excluded"` outcome.

Note: the engine would also hit the `no_professional_evidence` non-scoring criterion exclusion at line 106-112 if the first check were bypassed, because the candidate has `farrier.no_professional_evidence` confirmed with status `confirmed`. Both pathways produce the same block.
