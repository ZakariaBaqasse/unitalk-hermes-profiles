# Equinet n8n Discovery Control

Use this skill to start the exposed Equinet discovery orchestrator through n8n MCP, persist its execution identity, and create a finite Hermes cron monitor. n8n owns discovery and read-only HubSpot screening; Hermes owns terminal result retrieval, public-site enrichment, deterministic qualification/scoring, and review packaging.

## When to use

- A user authorises an A1 discovery run through the exposed main n8n orchestrator.
- An existing n8n execution needs restart-safe polling and exactly-once result consumption.
- A fresh cron session must resume work without relying on the initiating chat.

Do not use this skill to modify, publish, expose, or delete n8n workflows; write to HubSpot; stage records in Twenty; or initiate outreach.

## Prerequisites

1. The Equinet profile's `n8n` MCP connection is live and exposes the main orchestrator only.
2. Discover the actual MCP tool names and argument schemas in the current session. n8n documentation calls the execution-detail role `get_workflow_execution`; the deployed Hermes runtime may register it under a prefixed name such as `mcp__n8n__get_execution`.
3. The initiating session has the agent-callable `cronjob` tool. A cron-run session must never create, update, pause, resume, or remove cron jobs recursively.
4. Work from the Equinet profile root. Store tickets under `runtime/n8n-poll-tickets/` and result artifacts under the application run directory.
5. Confirm the request is within the Hermes runtime limits, no-outreach boundary, and human-review policy. n8n owns source policy and provider preflight.
6. Accept a requested total from 1 to 200. Reject values above 200; never split a request into several runs to evade this ceiling.

Current runtime note: Hermes 0.19.1 does not expose session heartbeat management as an agent-callable tool. Use cron, not `/heartbeat`, for autonomous durable monitoring.

## Poll-ticket commands

The helper is stdlib-only and writes atomically under a per-ticket lock. Its schema is `references/poll-ticket.schema.json`.

```text
python3 scripts/poll_ticket.py show --file <ticket.json>
python3 scripts/poll_ticket.py expire --file <ticket.json>
python3 scripts/poll_ticket.py next-action --file <ticket.json>
python3 scripts/poll_ticket.py observe --file <ticket.json> --execution-status <status>
python3 scripts/poll_ticket.py claim-result --file <ticket.json>
python3 scripts/poll_ticket.py mark-retrieved --file <ticket.json> --result-sha256 <sha256> --artifact-reference <path>
python3 scripts/poll_ticket.py mark-consumed --file <ticket.json> --artifact-reference <review-path>
python3 scripts/poll_ticket.py mark-delivered --file <ticket.json> --delivery-reference <target-or-message-id>
```

`claim-result` is the exactly-once gate. Set it before the MCP data call. A ticket in `recover_claim` is deliberately not auto-retried because a process crash may have occurred after the remote retrieval but before local persistence. Human recovery must inspect the run before deciding whether another retrieval is safe.

`consumed_at` means the final n8n envelope was transformed into validated Hermes-owned artifacts. `delivered_at` records that the terminal summary was emitted to the selected delivery path; it is not proof that a human read it.

## n8n polling rules

- Poll `get_workflow_execution` (or its runtime-discovered execution-detail alias) with metadata only: `includeData: false`.
- Treat `new`, `queued`, `running`, and `waiting` as non-terminal.
- Treat success as the only state allowed to retrieve result data.
- Treat error/failed/crashed, cancelled, and deadline expiry as terminal without result retrieval.
- On success, retrieve only `Build Final Discovery Result` with `includeData: true`, `nodeNames` restricted to that node, and `truncateData: 1`.
- Never use MCP execution data to transport raw crawls or unbounded lead sets. Those remain in n8n/Postgres/object storage.
- If execution retention has pruned the final data, report an unrecoverable retrieval blocker; do not rerun the workflow automatically.

## Failure and recovery

- **MCP unavailable:** preserve the ticket and report the exact connectivity/tool-discovery blocker.
- **Unknown n8n status:** do not coerce it to success; preserve raw evidence and stop for review.
- **Deadline exceeded:** mark `timed_out`, emit one terminal notice, and do not start another execution.
- **Result claimed but not retrieved:** use `recover_claim`; inspect the n8n execution and local artifact directory manually.
- **Processing failure after retrieval:** leave `consumed_at` null so a later finite tick can resume deterministic Hermes processing from the saved artifact without another MCP data retrieval.
- **Delivery retry:** `delivered_at` prevents later ticks from emitting the terminal message repeatedly. If transport confirmation is required, record the platform message ID in `delivery_reference` through a separately verified delivery mechanism.
- **Finite monitor exhausted before terminal state:** leave the ticket undelivered, report the unresolved execution through the job's last output, and require a human to extend or replace the monitor from a non-cron session.

# Post-n8n Public Website Enrichment

Use this skill at the boundary where n8n has finished discovery and deduplication. n8n supplies compact run metadata and leads; Hermes owns official-website research, cited evidence, classification, qualification, confidence and scoring.

## Boundary

Accept the compact `a1.discovery-result.v1` envelope from `Build Final Discovery Result`. Its canonical fields are `contract_version`, top-level `run_id`, and unique `leads[].lead_fingerprint` values. Preserve each lead exactly as supplied. The script accepts the earlier `schema_version`/`run.run_id`/`lead_id` shape only for existing fixtures and migration recovery.

Do not:

- rediscover, broaden, merge or deduplicate n8n leads;
- treat a lead name, category, directory snippet, map result or candidate website as verified evidence;
- call Firecrawl or any web service from the local script;
- generate claims, excerpts, URLs, classifications or criterion statuses in the deterministic script;
- claim HubSpot/Twenty checks, outreach permission or A2 approval.

The script has no Hermes web-tool API and no Firecrawl credentials. Website retrieval is always an agent/tool action.

## Authoritative dependencies

Resolve from the active profile home:

## Checkpoint workflow

1. Initialise one durable state file from the unchanged n8n handoff:

```text
/opt/hermes/.venv/bin/python skills/post-n8n-public-website-enrichment/scripts/manage_enrichment.py init <discovery-result.json> --state <state.json> --max-retries 2
```

Completion criterion: the state reports every n8n `lead_fingerprint` as `pending`, with `enrichment: null`; no evidence or website fact has been synthesized.

2. Request a stable pending batch:

```text
/opt/hermes/.venv/bin/python skills/post-n8n-public-website-enrichment/scripts/manage_enrichment.py next --state <state.json> --batch-size 5
```

`next` is read-only. Re-running it before acceptance or failure returns the same pending slice, which permits safe resume after interruption.

3. Research each returned lead as Hermes. Use `web_search` only to locate a plausible official domain, then use `web_extract` on destination pages for retained evidence. Apply the Public Website Enrichment Policy and blocklist, respect terms/robots/access controls, and stop on CAPTCHA, login, paywall, 403, 429 or other blocking control. Do not use search snippets as final evidence.

4. Create `a1.website-enrichment-results.v1`. Every completed lead must include:

- `research_method: hermes_approved_web_tools`;
- an HTTP(S) `official_website_url`;
- at least one destination-page citation retrieved with `web_extract` on that official domain;
- for every evidence item: stable evidence ID, destination URL, source name, retrieval time with timezone, exact excerpt, explicit claim, direct/inference/conflict label and retrieval tool;
- explicit `missing_information` and `conflicts` arrays, including empty arrays when none are known.

Each enrichment result uses `lead_id` as the processing identifier, set exactly to the source lead's `lead_fingerprint`. Optional `classification_decision`, `qualification_assessment` and `confidence_assessment` objects must be authored by Hermes from the cited evidence. Every evidence ID they reference must occur in the accepted enrichment evidence.

5. Validate and checkpoint completed results atomically:

```text
/opt/hermes/.venv/bin/python skills/post-n8n-public-website-enrichment/scripts/manage_enrichment.py accept --state <state.json> --results <results.json>
```

A result is rejected if it lacks cited destination evidence, uses an unapproved tool, cites a different domain, references uncited evidence or attempts to complete an unknown/already completed lead.

6. Record retriable failure with a caller-supplied audit timestamp:

```text
/opt/hermes/.venv/bin/python skills/post-n8n-public-website-enrichment/scripts/manage_enrichment.py fail --state <state.json> --lead-id <lead-id> --error <message> --recorded-at <ISO-8601>
```

Add `--terminal` for a non-retriable failure. Retriable failures remain pending only within `max_retries`; exhausted leads become `failed`. Never convert a failed lookup into invented enrichment.

7. When all three optional downstream inputs are present, execute the existing wrappers:

```text
/opt/hermes/.venv/bin/python skills/post-n8n-public-website-enrichment/scripts/manage_enrichment.py run-ready --state <state.json> --output-dir <artifacts-dir>
```

The command writes the supplied inputs, validates classification, builds qualification, builds confidence, prepares the scoring input, executes deterministic scoring and checkpoints artifact paths. Incomplete records are reported under `skipped`; the script never fills missing assessment inputs.

## Evidence rules

- n8n fields are discovery context, not evidence for a confirmed criterion.
- `web_search` results identify destinations only. At least one `web_extract` destination citation is mandatory for completion.
- Retain exact excerpts and page URLs. A claim must not be stronger than its excerpt.
- Preserve unknowns and contradictions. Never infer horse count, commercial status, ownership, purchasing authority or private contact details.
- Multiple pages on one official domain remain one source for corroboration.
- Publication does not create consent or authorise outreach.

## Handoff

Classification starts only after accepted website enrichment. Pass the unchanged n8n lead, official website evidence, missing information and conflicts forward. The new script orchestrates existing wrappers but does not replace their decision rules.
